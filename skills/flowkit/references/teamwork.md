# Delegation and handoffs

Use the host's native subagents when available, authorized by the user or applicable instructions, and independent work has enough value. The default is one implementer. A normal bounded change does not need a permanent team. Two parallel researchers or disjoint frontend/backend files can help; overlapping edits need sequencing or separate worktrees with planned integration.

Each dispatch states objective, exact input artifacts, acceptance, file ownership, allowed tools/side effects, required output and resource bound. Give raw requirements for an independent review rather than your preferred conclusion. Keep agent count within the current session limit, normally at most two specialists plus coordinator. Model/effort changes follow user/environment policy; do not hardcode obsolete model names. No blind retry loops: after two failed hypotheses summarize evidence and reassess; stop unsafe external retries on the first unknown outcome.

Coordinator reads returned artifacts, resolves conflicts and reruns appropriate integrated checks. Important architecture/security changes require human decision or suitable independent review before adoption. An agent's assurance is not verification. Preserve path/branch, changes, tests, known failures, decisions and next action in repository state. A fresh developer should not need private chat history.

If native agents or worktrees are unavailable, execute sequentially and say so. Role labels in a document are not proof an agent ran. Do not substitute new user-owned Codex chats for temporary subagents.
