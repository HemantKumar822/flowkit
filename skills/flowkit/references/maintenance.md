# Maintenance and learning

Use `status` and `doctor` before inventing project state. `status --live` fetches linked GitHub issues; without it the local issue reference is not current remote evidence. Required checks with no result remain unknown. Decisions and reusable lessons live in the project state via `decision` and `lesson`; do not retain whole chats or credentials. Commit `.flowkit/project.json` for team continuity after inspecting it for sensitive test output. Redaction is best effort, not a secret store.

Improve via Observe → propose → isolated test → compare → human approval → explicit update. Record a measurable defect/overhead and change only what the evidence supports. Version the change and changelog. Do not self-install capabilities, weaken checks, update third-party skills or silently change global instructions. Use the evaluation scenarios in the repository; baseline results may be equal and should be reported honestly.

`install` copies this self-contained skill to the selected host/scope directory; default Codex user target is `~/.agents/skills/flowkit`. It touches no existing global AGENTS/config/Superpowers files. An identical install is a no-op. Review code and run source-checkout tests before `install --update`; previous owned versions move to the printed backup path (default Codex uses `~/.codex/flowkit/backups`, other targets use `~/.flowkit/backups`). Repeat the original `--host`, `--scope`, `--project` or custom `--skills-dir` options for every update/removal. `uninstall` preserves a recoverable backup and refuses modified/foreign/link paths. Do not bypass refusal: preserve edits and compare against the manifest. Choose `--skills-dir` and `--backup-root` for a temporary clean environment.

Rollback: uninstall the current unmodified owned version using the original target options, then run `node <backup>/scripts/flowkit.mjs install` with those same target options from the prior backup. For pre-0.2 backups, use their supported `--skills-dir` with the exact original skill parent instead of unsupported host flags. Its ownership file is regenerated. Global configuration was never modified. If an operation crashes with a lock, read the lock's PID/time, confirm that writer is no longer running, preserve a copy of project state, then remove only that lock. Never automatically steal a lock on a timer.

Fingerprint excludes operational `.flowkit` files and configured root-relative generated paths; node_modules and .git are excluded at any depth. Goal, acceptance and config are included separately. Changes inside excluded paths are not detected; review exclusions when generated and source locations overlap. Source symlinks/junctions fail closed rather than claiming content freshness. External services/environment are not content-bound; rerun relevant checks after those change. This is an engineering freshness aid, not an adversarial attestation system.
